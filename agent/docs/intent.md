# 需求意图 intent.md

状态:计划阶段制品,待用户确认。来源:`赛题要求总结.md`、`设计书.md`、`工作流程.md`。已确认要求不得改动,新增内容只追加到文末"变更记录"。

## 1. 问题

- 销售顾问手上资料分散、型号易混、不知道对什么客户讲什么,写出的内容常与平台不匹配,且有价格误导、绝对化用语等合规风险。
- 评分标准是"生成结果能不能带来生意",不是文章写得好看。
- 全链路中断一次扣 10 分,因此稳定性优先于功能数量。

## 2. 期望结果

1. 输入产品、目标人群、场景、发布平台、客户描述,信息不足时先追问,不硬写。
2. 读出客户处境,输出带判断依据的洞察卡,共情锚点落到具体细节。
3. 按场景选切入点,按平台决定结构、语气、图数、行动引导,换场景或平台差异可解释。
4. 事实与图片只来自 ima 共享知识库"任德耀新建华为PC知识库";搜索为空时回退目录浏览,仍无则标"待确认"。
5. 型号精确匹配,相近型号不混淆;图片型号与文案一致。
6. 软文逐条事实核验、独立合规检查,无依据内容删除或标记。
7. 报价只引用知识库有依据的价格并展示算式与出处;知识库没有的价格、补贴一律拒绝并标"待确认"。
8. 输出演示脚本(新店员能照做)和下一步动作。
9. 页面分区:场景判断、知识库依据、图文软文、核验结果,另加客户洞察卡、演示脚本与下一步动作。
10. 支持删减、换渠道、替换卖点后重新生成,支持复制与导出文本。
11. 任一阶段失败按降级处理,整条链路不中断。

## 3. 约束

- 项目代码目录:`D:\vibe\aix\_download\agent`;所有文件只在 `D:\vibe\aix` 内操作。
- 自研 Agent:场景解析、平台规则、核验、合规由自己的代码和提示词完成;ima 只提供事实与图片;不得由 ima 直接生成最终软文。
- 架构:外层业务 Harness + 内层 `codex exec`(每阶段无状态调用,JSON Schema 输出,只读沙箱),不修改 Codex 源码。
- 系统提示词至少 8 个模块:角色与任务、场景理解、平台规则、知识库约束、图片规则、生成要求、核验规则、合规规则。
- 凭证只走环境变量 `IMA_OPENAPI_CLIENTID`、`IMA_OPENAPI_APIKEY`(及模型相关变量);不进代码、README、日志、截图、视频;界面只显示脱敏尾号。
- ima 知识库只读,不得删除、修改、对外传播;知识库 ID 仅程序内部使用。
- 红线:图片非 ima 来源或型号不符、虚构价格/补贴/销量/奖项/评价,对应项计 0 分。
- 资料冲突时停止输出并提示人工确认。
- 不入库:`.env`、`.cache/`、`node_modules/`、`.npm-cache/`、`.codex-home/`、`out/`、`codex-src/`。
- 截止:初赛当日 17:00;取舍顺序:全链路不中断 > 事实准确与不虚构 > 体验与展示。
- 开发并行不超过 3 路,独立 worktree;验收清单只能改 `passes`。
