# 完整版业务 Harness 与 Codex 内层实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 恢复原赛题与设计书的完整业务闭环，以真实 Codex 内层承载语言任务，以指定 ima 作为正式事实和图片来源，完成原 55 项独立验收。

**Architecture:** Web → 本地 HTTP/SSE → 八阶段业务 Harness → Codex CLI；检索、规则、Schema、核验与金额运算为外层确定性代码。Codex 默认走 Responses；只支持 Chat Completions 的服务经显式本地协议桥接接入，不静默改成 HTTP 直连。测试 fixtures 与正式来源分离，不能据此提高真实链路验收状态。

**Tech Stack:** Node.js ≥20、ES modules、Ajv 8.17.1、官方 ima Skill 1.1.10、固定源码来源的官方 Codex CLI。

## 依据与版本边界

- 原始来源：项目根 `华为·产业进阶赛道·赛题手册v4.pdf`（9页）、`赛题要求总结.md`、`设计书.md`、`工作流程.md`。
- 完整需求/独立测试以 `docs/full-scope-baseline.md`、`docs/full-qa-plan.md` 为交接文件；原 `docs/acceptance.json` 的55条描述与步骤不得改写，测试角色只改 passes。
- 用户明确的架构原话：在 coding agent harness 基础上外套 harness；直接下载开源 Codex CLI，在其基础上修改；需要原本程序而非安装包。此语境确定源码基座及 Codex 内层，未明确说必须现场本机编译成功，不能把源码仅作装饰或声称现二进制由该源码构建。
- lite：`release/lite@2d4b111`，3000；full：`develop/full@2263a8e`，3001。开发仅在 `feature/full-core` 独立工作树，不写 lite、master 或 full 集成树。
- 本机源码基线 `8c076942cb70fba8e5c4732c23f1faabc4aed484`；发现官方可执行 `codex-cli 0.162.0-alpha.17.2`。尚无 Rust/Cargo，尚未 source-build，须保留版本来源和能力探测结果。
- 用户“不用魔搭，直接用本地文件”作为交付偏好单列；不创建外部部署。每个完成任务由发布角色向已授权 GitHub 分支同步并回读。

## 固定不变量

1. 正式事实/型号/价格/图片仅来自指定 ima；仅四个读取接口，搜索空进入 P1 目录。未确认同源的镜像和 fixtures 不可成为正式来源。
2. 型号和图片身份来自资料自身，不能把请求型号回填成身份依据；冲突、错型号、无依据促销阻断正式成稿。
3. 价格绑定 SKU、渠道、地区、核验日期、来源；整数分算术；不要求报价的内容不因缺价格而永久阻断。
4. 八模块按阶段装配、替换占位符；每阶段输出经其 Schema；代码核验独立于生成，合规词表和语义复查独立执行。
5. 模型失败/不合 Schema 最多首次加两次重试；合规最多两轮改写，每轮重跑事实与合规。重试、耗时、切备均为实际事件。
6. 无凭证显示待配置；来源不全/语义复查不可用不宣称通过。`complete_with_pending` 仅为标明待确认的核对稿，冲突等阻断状态不可导出成稿。
7. 凭证只读进程环境/被忽略的 `.env`；不写模型提示词、文件日志、响应或截图。内部知识库/media/folder ID 不出站。

后端开发独占 `harness/pipeline.mjs`、`harness/stages/**`、`harness/tools/**`、`server/**`、`scripts/**`、`package.json`/lock、`.env.example`；规则/提示词/Schema 修改先向统筹报告。前端独占 `web/**`；QA 独占验收清单和 QA 报告；发布负责集成、版本边界及交付文档。

- 后端：批次1→2→3→4；协议桥接可在阶段契约稳定后独立；自检在runtime/数据接口稳定后接入。
