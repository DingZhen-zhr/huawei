## 3. 原架构与关键契约

- 原设计两层Harness：模型语言环节经 `codex exec` 无状态、只读沙箱和阶段JSON Schema；外层负责确定性规则、工具、编排、核验、合规。不能把lite默认HTTP直连默认为原要求已取消。服务不支持Responses时，按原设计讨论协议转换适配，保持实际驱动诚实可见。
- 八业务阶段为task、insight、strategy、retrieval、draft、verification、compliance、export；辅助模型调用questions/reco_text/verify_claims/compliance_review/rewrite不得冒充新增业务阶段。阶段输出版本/字段按Schema校验；外部$ref发模型前解析。
- 模型只能在规则集合内选择角度/排序，不能自造规则或产品事实；提示词按阶段组合、去frontmatter、替换声明占位符，外部资料与用户文字仅作数据。
- StageLog必须由实际时钟/调用记录产生status、ms、attempts、fallback；空字段显示未返回，不允许从UI占位推定后端已测。
- Fact与图片绑定自己的型号/来源/限定/版本；不允许仅把请求型号写入记录当作核验。引用id只做内部映射，kb_id/media_id/folder_id不出站。
- 价格仅知识库已记载的官方公开价与确切SKU/日期/渠道/地区；算术由代码完成。未知价格为null与待确认。资料冲突不能平均/择一；不交付冲突成稿。
- 镜像同源尚未确认：可实现并测试显式标注的离线回退，但不因镜像标签就认定满足真实ima来源；同源确认记录/正式复核分开列出。
- 当前简接口 `/api/tasks` 可以作为外层UI兼容层，不能用“接口简”删掉8阶段真实行为。模型/原始资料不直接作为可执行HTML展示。

## 4. 证据等级与状态

每条证据记录分支、SHA、端口、任务id、输入、操作、可见输出、来源模式、断言、实际文件或截图、剩余限制。

- `未测`：新版本未操作；不等于失败。
- `部分`：仅某步骤/某模式完成；不得置完整passes=true。
- `缺实现`：当前实现路径与原要求明确不符；写清具体行为或静态位置。
- `配置阻塞`：需要真实ima/模型/同源确认才能判断；不能伪造运行记录。
- `规则桩通过`：独立fixture覆盖算法/错误路径，明确标test_fixture，不能宣称真实ima来源或真实模型完成。
- `正式通过`：原条目的全部步骤和来源约束均满足、独立测试有可复查证据。纯输入/布局可通过真实网页确认；涉及ima来源的项还须真实接入证明。

不能因为没有凭证而不做规则/故障路径测试，也不能因为规则桩通过而绕开真实接入验收。
