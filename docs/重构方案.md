# 华采智营 · 门店导购智能体（复赛版）

> 一句话：**销售顾问把顾客的情况说一句，Agent 先问清楚，再给机型和话术；每个数字都能追到知识库。**
>
> 2026-10-20 修订：取消多页工作台、假看板与"五角色流水线"演示。产品收敛为**一个对话框**，两种模式。

---

## 1. 只做一件事

销售在顾客面前，没时间看仪表盘、时间轴和九宫格。

| 之前 | 现在 |
|---|---|
| 3 个 Tab、5 个角色、看板 | 一个对话框 |
| Mock 模板生成 | DeepSeek 多轮对话 |
| 演示型"返工" | 真实追问 + 真实推荐 |
| 假数据看板 | 删掉 |

**两种模式，同一个输入框：**

- **导购**：先问动机，再给 1-2 个机型 + 价格口径 + 下一步
- **写文案**：基于同一份知识库事实，直接出可发布内容，可复制

## 2. 对话为什么"像人"

### 2.1 苏格拉底式追问（硬约束，不只写在提示词里）

1. **一次只问一个问题**：代码检测回复里问号数量 > 1，自动重写一次，仍超就砍掉多余问句。
2. **先复述再提问**：开口先说"我听到的是……"，降低销售的理解成本。
3. **问动机不问参数**：不问"预算多少"，问"更在意一次投入，还是能用三四年"。
4. **两轮封顶**：已问过 2 轮且拿到预算 + 场景 → 强制给结论，本轮禁止出现问号。
5. **信息不够时只给方向**，不一次性甩 5 个机型。

实现：`app/server/chat/agent.mjs` 的 `countQuestions` / `shouldRecommend`。

### 2.2 事实从哪来

```
用户消息 → 槽位抽取（预算/场景/人群/偏好）
        → 结构化事实检索（10 张型号卡：身份/屏幕/性能/便携/协同/人群）
        → 预算过滤（超预算 15% 不推荐）
        → 价格兜底（该型号官方公开价，带 SKU 数与快照日）
        → 注入 system prompt → DeepSeek
```

**为什么不用原来的向量检索做主路径？** 现有 `kb-index.json` 的 chunk 是整段 Markdown，
型号名只存在于文件名里，正文混着"字段 5 / 原执行时记录……"这类模板话术，
导致所有 chunk 的余弦相似度都挤在 0.72–0.76，检索等于没检索。
现在的做法是**事实级检索**：一句话一条事实、显式带型号，可引用、可核对。

向量索引保留作为兜底能力，后续按"型号名 + 小节标题"重建 chunk 后再启用。

### 2.3 不编造

- 资料里没有的（补贴、库存、赠品、活动期限）→ 明说"要门店确认"
- 价格只能来自该型号自己的价格卡，**禁止把 A 的价格安到 B 上**（提示词硬规则）
- 预算内无合适机型 → 给最接近的一台，并明说"超预算 899 元"

## 3. 代码结构

```
app/server/
  chat/agent.mjs        槽位抽取 / 事实检索 / 系统提示 / 多轮对话 / 问句收敛
  agent/kb-index.mjs    知识库解析：型号检索卡 + 官方价格快照 → 结构化事实
  deepseek.mjs          DeepSeek 调用（.env 读取，不入库）
  mcp/core.mjs          平台规则卡：adapt / review / publish（保留给写文案的合规校验）
  platforms/*.json      小红书 / 朋友圈 / 公众号 / 海报 规则卡
  index.mjs             POST /api/chat

app/src/
  pages/Chat.tsx        单屏对话（导购 / 写文案）
  lib/chat.ts           前端消息契约
```

---

## 4. 接口

```
POST /api/chat
{ mode: "guide" | "content",
  messages: [{ role: "user" | "assistant", content: string }] }

→ { reply, slots, facts: [{ model, text, source }], warning? }
```

`facts` 就是消息下方"依据 N 条"的来源，前端不额外加工。

---

## 5. 效果与边界

**能做的**
- 多轮追问，记住预算/场景/人群
- 基于 10 张型号卡 + 55 条官方价格记录给推荐
- 报价带 SKU、核验日、来源文件
- 超预算、缺依据时如实说明
- 一键切"写文案"，同一套事实出稿，可复制

**还不能做的（别在答辩里吹）**
- 语音输入
- 实时库存/补贴（知识库没有）
- 自动发布（小红书/朋友圈无开放接口）
- 跨会话记忆（刷新即清空）

## 6. 验证

```bash
cd app
node server/index.mjs     # 8787
npm run dev               # 3000
```

手工用例：

1. `顾客想买个轻薄本` → 只问一个问题，且问的是使用方式
2. `给学生用，主要上网课` → 复述 + 只问一个（携带还是宿舍）
3. `预算5000左右` → 直接给结论，明说 5,899 超预算 899
4. `客户嫌比竞品贵，怎么回` → 不急着讲参数，先区分"单纯比价"还是"觉得不值"
5. 切"写文案" → 小红书稿，事实与价格均来自知识库
