# 软文创意工作流（不改界面）

本轮基于回退后的 zxt `55243b3`，保留原作者界面、九阶段、图片挑选、复制发布正文、导出、平台切换及既有 DeepSeek 配置。仅将工作台正文从固定全参数模板改为创意策划与编辑流程。原 `docs/soft-article-plan.md` 仍为历史方案，本轮以用户“更吸引、艺术、线性递进和表现力；不改 UI”指令为准。

## 研究与设计推断

- Green / Brock，叙事运输研究：[The role of transportation in the persuasiveness of public narratives](https://researchconnect.buffalo.edu/en/publications/the-role-of-transportation-in-the-persuasiveness-of-public-narrat/)。借鉴人物处境、具体任务和连贯叙事；这不等于虚构个人体验或客户证言。
- Packard / Berger，具体语言研究：[How Concrete Language Shapes Customer Satisfaction](https://academic.oup.com/jcr/article/47/5/787/5873524)。将抽象“智慧高效”改成具体人物、物件和动作。研究情境不能直接外推为中文华为 PC 软文转化率提升。
- 阅读注意力研究：[Journal of Marketing 研究入口](https://journals.sagepub.com/doi/abs/10.1177/00222429231152880)。用于提出段落需推动阅读的设计假设，不以情绪刺激替代信息准确。
- Poynter 专业写作实践：[Thirty tools for writers](https://www.poynter.org/archive/2002/thirty-tools-for-writers/)。借鉴强动词、具体细节、长短句节奏和有节制的意象；它是写作实践建议，不是产品效果实验。
- 本地 P6《图文软文输出规范》要求一个主矛盾、图文节奏、三候选标题、人物任务阻碍开篇、事实与适用边界；《v6 多平台软文案例研究》案例 02 的“任务→原有步骤→动作→结果→条件”用于设计推进顺序。案例只提供写法，事实仍用 P1/P1-08 既有快照。

据此作出的工程推断：将创造和编辑拆成真实先后调用，使初稿接受独立诊断并据最弱环节重写，应该比把所有写作要求堆入一次提示更可检查。该推断仍需同事实盲评，不能把模型打分或测试通过当成艺术性、咨询率已提高的证据。

## 实际执行路径

1. 简报：从场景、目标和顾客原话提取动作、阻碍、想保住什么；模型收到完整简报，规则预览按可识别的需求线索改变角度与行动。
2. 策划：任务瞬间、选择张力、生活意象三角度；按相关、画面、证据、平台、新鲜度共 25 分择优；同时规划段落作用、读者问题、具体动作、事实 ID 和向下推进。
3. 初稿：围绕一个主矛盾写人物任务，产品在任务需要时出现。采用强动词、具体物件、长短句节奏，意象首尾照应。比喻不能暗示未证实性能。
4. 独立编辑：五维 1–5 分（吸引力、艺术节制、线性递进、表现动作节奏、平台与唯一 CTA），每个维度要求引用初稿真实原句及可执行修改或无需修改的具体理由；空依据、缺维度、伪造引用均退回规则预览。
5. 定向重写：任一维低于 4、编辑要求修改或硬门发现问题时，仅重写一次，优先事实风险，再修最弱的两项。最终仍需人工评阅，初稿自评分不冒充终稿验收。
6. 本地硬门：检查完整型号、事实短句及 ID、条件原文、数字白名单、显式虚构体验/权益和既有合规规则。失败退回清晰标记的规则创意预览。
7. 同稿交付：九阶段、完整导出和发布正文共用一次 `ArticleBundle`，复制不会触发重新生成。

模型可用时实际发生三至四次 DeepSeek 调用；复用原 `/api/deepseek` 代理和浏览器内既有 Key，无新网关、新设置界面或后台账号。单次调用最长 60 秒；没有 Key 则不发请求。调用失败、错误格式或硬门不通过都会通过原阶段内容说明规则预览状态，不伪造模型成稿、实时 ima 核验或“事实全部通过”。

## 场景、平台与价格兼容

八场景各有具体任务及主矛盾：开学书包与学习、职场会议衔接、创作选片改稿、家庭旧资料迁移、企业部署清单、门店一个体验问题、新品版本选择、节日送礼对象的日常。产品事实依任务排序：朋友圈只取一个主事实，其余平台最多两个产品事实；海报仍不超过三个卖点。

公众号按连续阅读推进；小红书按问题卡/证据卡/条件卡推进且不伪造第一人称体验；朋友圈一阻碍、一卖点、一私聊动作；海报保留主副标题、事实点、同屏条件和到店动作。图片仍用原作者来源索引和四平台原有数量、位置。

`withPrice` 保留原有触发条件：公众号与朋友圈的任意场景，或新品、海报、门店到访中开启时引用原 P1/08 官方页面价格卡，带 2026-10-17 历史快照日期，说明未实时核验、非当前成交价、以发布当日官方渠道和结算页为准。关闭时不写金额。未知补贴、赠品、库存和优惠不生成。

## 同事实短对照（规则预览示意，不是模型实测）

示例：MateBook Pro 内容创作、小红书。事实相同：14.2 英寸 3:2 OLED 触控屏，3120×2080，sRGB/P3 典型值，柔光仅柔光版；SSD 按销售配置；原生接口较少，必装软件需先验证。

原入口开头：
> 先给结论：轻量化 + 3:2 高分辨率 OLED 触控 + 鸿蒙协同。但值不值得买，取决于你的任务，不看形容词。

新规则预览开头：
> 选片窗口开着，改稿消息又亮了，素材还等着整理。
>
> 创作需要专注，选电脑却容易被一长串参数带偏。

中段仅围绕屏幕与素材容量给有绑定的事实，再保留软件、外设与版本核验边界；结尾回到“让窗口里的下一步，是作品本身”。此对照展示表达方式变化，没有杜撰亲测、创作速度或画质效果。模型模式还会对该初稿独立编辑、定向重写。

## 验证与边界

运行 `npm test` 和 `npm run build`。测试包括 3 型号×8 场景×4 平台（96 组合）、多轮调用与低分重写、失败/错误 JSON/虚构数字退回、导出同稿、简报角度变化、任务错配拦截、价格开关和 Home JSX 与回退基线逐字相同。

这不是语义全知的事实核验器：即便数字与短句一致，附加功能推论、现场演示结果、图片授权与实时价格仍须人工核验。未接真实 Key 的验证只使用可控模型返回，不能声称真实 DeepSeek 成稿质量或 ima 全链路已验收。建议用相同事实包和任务做旧/新匿名双稿，让至少两位评阅者按五维评分并比较依据、条件、唯一 CTA，同时记录咨询意愿；无实测数据不宣称业务提升。
