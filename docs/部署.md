# 部署说明（Supabase + Netlify）

> 当前后端持久化：Supabase Postgres。未配置 `SUPABASE_*` 时自动回退本地 JSON（仅开发）。
> 部署前先跑迁移；Netlify 同时托管前端静态站点和 `/api` Functions。

## 1. Supabase

| 项 | 值 |
|---|---|
| 组织 | 石头鸡白毛 |
| 项目 | huacai |
| Ref | `wetrxsiobiwyeavianvv` |
| 区域 | ap-southeast-1（新加坡） |

### 1.1 应用迁移

在仓库根目录：

```bash
cd app
npm run db:migrate
```

迁移文件在 `app/supabase/migrations/`：

- `20261020000000_init.sql`：旧会话/消息/facts（保留兼容）。
- `20261022000000_huacai_refactor.sql`：stores、store_profiles、fact_ledger、content_tasks、content_variants、task_events、audit_logs。
- `20261023000000_persistence.sql`：`stores.demo`、`content_tasks.payload`、`runtime_state`（价格冲突确认/候选事实）。

迁移是幂等的，可重复执行。迁移脚本用 `SUPABASE_DB_URL`（直连 5432）或 `SUPABASE_POOLER_URL`（6543）。

### 1.2 表与数据

| 数据 | 表 |
|---|---|
| 门店 / 门店资料 | `stores` + `store_profiles` |
| 内容任务 | `content_tasks`（完整快照在 `payload`） |
| 五渠道版本 | `content_variants`（完整版本在 `content`） |
| 价格冲突确认 / 候选事实 | `runtime_state`（key: `ledger`、`fact-proposals`） |
| 审计（预留） | `audit_logs` |

演示门店在第一次访问「进入演示门店」时自动创建（`HUAWEI-001 / 246810`，`demo=true`）；生产环境请把 `HC_DEMO_MODE` 设为 `false` 并单独建门店。

RLS 已开启；后端用服务端数据库连接直连，前端不直连数据库。

## 2. 环境变量

Netlify Site configuration → Environment variables：

| 变量 | 必填 | 说明 |
|---|---|---|
| `DEEPSEEK_API_KEY` | 是 | 五渠道模型写作 |
| `DEEPSEEK_MODEL` | 否 | 默认 `deepseek-chat` |
| `DEEPSEEK_CONTENT_MODEL` | 否 | 内容模型，默认继承 `DEEPSEEK_MODEL` |
| `HC_PERSISTENCE` | 是 | 填 `supabase` |
| `SUPABASE_POOLER_URL` | 是 | Supabase 连接池（6543），Serverless 用这个 |
| `SUPABASE_DB_URL` | 否 | 直连（迁移/本地脚本用） |
| `HC_SESSION_SECRET` | 是 | ≥32 字符；生产缺失会启动失败 |
| `ADMIN_PASSCODE` | 是 | 管理后台口令；生产缺失会启动失败 |
| `HC_DEMO_MODE` | 演示填 `true` | 生产正式环境建议 `false` |
| `HC_GENERATION` | 否 | 默认模型；填 `rules` 强制规则稿 |
| `TAVILY_API_KEY` | 否 | 官方来源搜索；不填则跳过 |
| `HC_MODEL_REPAIR` | 否 | Serverless 默认关闭自动修复；填 `true` 开启 |

`HC_INLINE_TASKS` 不需要手动设置：Vercel/Netlify 下自动内联生成（POST 直接等结果，避免函数返回后丢任务）。

本地 `.env` 可以填同一套 Supabase 变量；`npm test` 会强制 `NODE_ENV=test` + `HC_PERSISTENCE=local`，不会写生产库。

## 3. Netlify（前端和 API 同站点）

在 Netlify 创建站点并连接 Git 仓库，构建设置为：

```text
Base directory: app
Build command: npm run build
Publish directory: dist
Functions directory: netlify/functions
```

`netlify.toml` 已配置 `/api/*` 到 Express Function 的重写，以及前端 history fallback。不要设置 `VITE_API_BASE_URL`，前端 API 请求和登录 Cookie 会保持同源。

在 Site configuration → Environment variables 中设置第 2 节的变量。另需设置：

| 变量 | 正式值 |
|---|---|
| `NODE_ENV` | `production` |
| `HC_DEMO_MODE` | `false` |
| `HC_PERSISTENCE` | `supabase` |
| `HC_SESSION_SECRET` | 至少 32 字符的随机字符串 |
| `ADMIN_PASSCODE` | 正式管理员口令 |
| `DEEPSEEK_API_KEY` | DeepSeek 密钥 |
| `SUPABASE_POOLER_URL` | Supabase 6543 pooler 连接串 |
| `CORS_ORIGINS` | 留空，同站点不需要跨域 |
| `COOKIE_SAME_SITE` | 留空，默认 `lax` |
| `VITE_API_BASE_URL` | 留空 |

密钥只保存在 Netlify 环境变量中，不要提交到仓库。保存变量后触发部署。

- `netlify/functions/api.mjs` 复用 Express 应用。
- Netlify 同步 Function 当前最长运行 60 秒；Serverless 环境模型单次尝试超时后会回退规则稿。
- 页面使用事件流和轮询更新任务进度；轮询也能在事件流不可用时刷新状态。

部署后打开 `https://你的站点.netlify.app/api/health`，确认返回 `persistence: "supabase"` 且数据库为 `up`，再从首页登录正式门店。

### 3.1 数据库迁移和创建正式门店

先在本地配置 Supabase 连接并运行迁移：

```powershell
cd app
$env:SUPABASE_DB_URL="你的 Supabase 5432 直连串"
npm run db:migrate
```

关闭演示模式后，创建一个正式门店（仅需执行一次）：

```powershell
$env:NODE_ENV="production"
$env:HC_PERSISTENCE="supabase"
$env:SUPABASE_POOLER_URL="你的 Supabase 6543 pooler 串"
$env:SEED_STORE_CODE="STORE-001"
$env:SEED_STORE_NAME="杭州体验店"
$env:SEED_STORE_PIN="你的4到6位数字PIN"
npm run db:seed-store
```

运行命令的电脑需要能访问 Supabase。

## 4. 本地

```bash
cd app
npm install
npm run db:migrate      # 首次
npm run server          # 8787
npm run dev             # 3000
```

不配置 Supabase 时自动用 `app/server/data/runtime/*.json`；换机器会丢任务，仅适合本地临时开发。

## 5. 知识库与图片

- 仓库不包含 `华为PC全板块深度知识库_v7/`（合规）。部署环境没有该目录时，`server/agent/kb-index.mjs` 回退到 `server/fixtures/kb-facts.json`（10 个型号、55 条价格）。
- 官方产品图在 `app/public/media/`（3 张）；其余型号会提示「官方产品图未就位」。
- 配图在前端 Canvas 生成，不落对象存储；导出 ZIP 由浏览器下载。

## 6. 已知限制

- 内容任务保存 30 天，但没有自动清理任务；需要时可加定时 SQL。
- 顾客问答是确定性规则，不落库（前端 7 天本地会话）。
- Supabase Storage 未使用；门店二维码只支持外链地址。
- 迁移脚本需手动执行；Vercel 构建不会自动跑 DDL。

## 7. 前后端分开部署（可选）

如果之后有可用的独立 Node 服务平台，可把前端与后端拆开。前端设置 `VITE_API_BASE_URL` 为后端根域名；后端设置 `CORS_ORIGINS` 为前端完整来源、`COOKIE_SAME_SITE=none`，并要求两边都使用 HTTPS。Netlify 同站点部署不需要这些跨域配置。

### 7.1 前端平台

项目根目录选择 `app/`，构建配置使用：

```text
Install command: npm ci
Build command: npm run build
Output directory: dist
```

前端环境变量：

```text
VITE_API_BASE_URL=https://api.example.com
```

这里填写后端完整域名，不要在末尾加 `/api`。

### 7.2 后端平台

项目根目录选择 `app/`，启动命令使用：

```text
npm run server
```

生产环境变量至少需要：

```text
NODE_ENV=production
PORT=10000
DEEPSEEK_API_KEY=你的密钥
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-chat
DEEPSEEK_CONTENT_MODEL=deepseek-chat
HC_GENERATION=model
HC_PERSISTENCE=supabase
SUPABASE_POOLER_URL=你的6543连接串
SUPABASE_DB_URL=你的5432直连串
HC_SESSION_SECRET=至少32字符的随机字符串
ADMIN_PASSCODE=正式管理员口令
HC_DEMO_MODE=false
CORS_ORIGINS=https://你的前端域名
COOKIE_SAME_SITE=none
```

平台必须把外部端口映射到 `PORT`，并提供 HTTPS。`COOKIE_SAME_SITE=none` 只适用于前后端不同域名的情况，并且要求 HTTPS。

### 7.3 初始化数据库和正式门店

迁移只执行一次。在本地配置生产数据库连接后运行：

```powershell
cd app
npm run db:migrate
```

关闭演示模式后，需要创建一个正式门店。设置以下临时环境变量后运行：

```powershell
$env:NODE_ENV="production"
$env:HC_PERSISTENCE="supabase"
$env:SUPABASE_POOLER_URL="你的6543连接串"
$env:SEED_STORE_CODE="STORE-001"
$env:SEED_STORE_NAME="杭州体验店"
$env:SEED_STORE_PIN="你的4到6位数字PIN"
npm run db:seed-store
```

部署后先打开 `https://api.example.com/api/health`，确认返回 `persistence: "supabase"` 且数据库状态为 `up`，再打开前端地址登录。
