## 0. 一句话定位

**华采智营不是“会写文案的聊天框”，而是给一线门店销售使用的“门店内容副驾驶”：用一句话、少量追问和真实产品事实，快速产出可发布的多平台内容包，并在发布前拦住所有没有依据的数字和承诺。**

主入口：**内容工坊**。  
辅助入口：**顾客问答**。  
两者共享同一套产品事实、门店口吻、真实细节和核验能力。

### 不做什么

- 不做效果看板、成交看板、虚假数据仪表盘。
- 不做多 Agent 角色 UI、角色头像、九宫格流水线表演。
- 不做轻 CRM、顾客长期档案、跟进状态管理。
- 不做自动发布、自动登录平台、自动托管评论区。
- 不做“模型凭常识补全产品事实”。
- 不做假产品图、假二维码、假门店活动、假顾客评价。
- 不把门店销售变成总部内容审核员。

## 1. 用户、场景与成功标准

### 1.1 唯一首要用户

**一线门店销售。**

典型状态：顾客就在面前，或刚接待完，手机在手边，时间碎片化，不愿意写长文，也不愿意填表。

次要角色：

- 店长：事后抽查内容，不阻塞销售发布。
- 总部/运营管理员：维护产品事实、来源、冲突、门店码和素材，不进入销售主流程。

### 1.2 核心场景

1. 门店当天要发一条内容，不知道发什么，点“今日任务”。
2. 顾客说“预算 6000，主要剪视频/上网课”，销售现场问选型和话术。
3. 销售从顾客问答一键转成跟进内容，补一个真实细节，生成五渠道内容包。
4. 销售选中一个版本，按需生成配图，复制或导出整包。
5. 系统发现无依据价格/参数，直接阻断并展示来源或缺口。
6. 新品发布，管理员在 `/admin` 粘贴官方资料，确认冲突后全门店立即可用。

### 1.3 成功标准

- **内容成功**：最多轻改一次即可发布；只允许改店名、称呼、CTA、门店真实联系方式等本地信息。
- **事实成功**：所有产品事实与商业承诺都能追到来源；无依据数字不可复制/导出。
- **操作成功**：手机端可完成完整闭环；从打开到拿到文字内容包，目标 ≤ 90 秒（不含按需生图）。
- **视频成功**：3 分钟内能连续看到“现场问答 → 五渠道内容 → 按需配图 → 错误价格被拦 → 整包导出”。

## 2. 已锁定的产品决策

| 维度 | 决策 |
|---|---|
| 首要用户 | 一线门店销售 |
| 设备 | 手机全流程；平板两栏；桌面三栏 |
| 交付形态 | 响应式 Web + PWA，可添加到桌面，不上应用商店 |
| 主入口 | 内容工坊 |
| 辅助入口 | 顾客问答 |
| 渠道 | 小红书、朋友圈、公众号、海报、视频号，全部保留 |
| 短内容候选 | 小红书、朋友圈、视频号各 3 个角度；公众号、海报各 1 版 |
| 三个角度 | 痛点切入 / 避坑与选择 / 真实场景故事 |
| 追问 | 不固定问题数，最多 6 个；信息足够直接生成；一次只问一个 |
| 追问选项 | 3 个快捷选项 + “都不是，我来说” + 语音输入 + 可跳过 |
| 真实细节 | 生成前硬门槛：必须有一个销售提供的真实场景细节；缺了不能生成 |
| 内容模型 | 创意与评审使用 `deepseek-v4-pro`；事实抽取/核验用低温度；允许降级到独立评审调用 |
| 事实来源 | 知识库 + 华为官方域 + 用户指定官方链接 + Tavily 发现；不自动采信广义网页 |
| 搜索 | 缺资料时自动 Tavily 搜索，显示进度；只找来源和正文，不直接写事实 |
| 冲突 | 冻结相关字段，管理员确认前不得生成价格/参数断言 |
| 核验 | 产品事实与商业承诺硬阻断；无依据不可复制/导出 |
| 人工审批 | 默认无人工审批；事实核验通过即可导出；店长/总部可事后抽查 |
| 产品图 | 只用官方素材或门店实拍；AI 只做场景、光影、排版、比例 |
| 图片文字 | Canvas/HTML 模板确定性绘制，AI 不生成中文文字 |
| 生图时机 | 按需生成；文案先交付，图片不阻塞 |
| 图片数量 | 由图片规划器根据场景、渠道、候选和素材决定，不询问销售固定张数 |
| 二维码 | 不生成假二维码；使用门店真实配置，未配置则留白/提示补充 |
| 竞品 | 公开内容仅在销售提供可核验官方资料后，允许中性引用；无来源阻断 |
| 门店隔离 | 多门店共享产品库；门店码 + PIN；门店口吻/素材/历史隔离 |
| 会话保存 | 顾客问答 7 天自动删除；不进入 CRM，不训练模型 |
| 后台 | 独立 `/admin`，管理员口令进入 |
| 导出 | 整包 ZIP + 单渠道复制 + 单图下载；手机优先系统分享 |
| 视觉 | 米白纸感、墨黑、少量华为红；Operate 工具模式，不做 AI SaaS 模板 |
| 截止 | 10 月 23 日 17:00 硬截止；功能不砍，分阶段交付 |

### 2.1 关键默认假设

- 价格事实快照超过 **7 天**自动标记 stale；带价格内容触发重新搜索/确认，未解决则不带价或阻断价格字段。
- 非价格事实默认 90 天复查。
- Tavily 单任务最多 3 次查询、总等待上限 20 秒；超时进入安全版/待补。
- 内容任务保存 30 天；顾客会话保存 7 天。
- 现有平台规则卡中的 `required` 字段继续生效（如小红书 AI 标识、公众号来源说明）；由管理员后台配置，不可静默删除。
- 门店二维码、地址、电话、营业时间必须来自门店配置；没有就留白，不生成占位码。
- 官方产品图仅用于授权门店营销；门店实拍必须勾选“本人拍摄/已获授权”。第三方图片不得抓取使用。

## 3. 页面与信息架构

### 3.1 路由

- `/`：今日任务台
- `/create`：新建内容任务
- `/create/:taskId`：内容包工作台
- `/ask`：顾客问答
- `/settings`：门店资料、口吻、二维码、联系方式
- `/admin`：独立后台（销售端不显示入口）
- 旧临时页面/旧演示入口：不得继续暴露假型号或假数据；必要时保留代码但从主路由移除。

### 3.2 手机端

底部固定三项导航：

1. 今日
2. 内容
3. 问答

顶部：当前门店名、设置入口。  
内容页单列；先看平台预览，展开后编辑。  
证据、图片素材、风险以底部抽屉打开，不跳走主任务。  
所有触控目标 ≥ 44×44px；不依赖 hover。

### 3.3 平板

两栏：左侧任务/渠道导航，右侧当前平台预览与编辑。  
证据与素材为可收起侧栏。

### 3.4 桌面

三栏工作台：

- 左：任务、渠道、候选角度
- 中：平台原生预览 + 编辑
- 右：事实依据、风险、图片素材、门店真实信息

不把三栏做成后台仪表盘；中间内容预览是视觉主角。

## 4. 关键交互流程

### 4.1 内容工坊主路径

1. 首页展示 3 张今日任务卡。
2. 任务卡来自系统规划：日期节点 + 在售产品事实 + 门店画像 + 最近内容，不允许出现无资料/无素材的假选题。
3. 点卡进入 `/create`，预填产品、场景、目标人群。
4. 系统按缺失信息追问，最多 6 个，一次一个。
5. 必须拿到一个真实细节，才允许提交生成。
6. 创建后台任务，展示阶段：检索 → 规划 → 写作 → 评审 → 核验。
7. 文字先出；每个渠道先展示推荐稿 + 备选角度 + 风险状态。
8. 图片按需生成；先展示配图计划，不自动批量生图。
9. 销售可选择、改写、重新生成、补来源、导出。
10. 失败渠道单独重试，不浪费已成功渠道。

### 4.2 追问原则

- 一次只问一个问题。
- 每问提供 3 个有意义的快捷选项 + “都不是，我来说” + 语音输入。
- 问题必须改变实现/内容：发给谁、真实场景、使用方式、真实细节、目标动作等。
- 信息已够时直接生成；不能为了“走流程”硬问。
- 最多 6 个是上限，不是默认值。
- 追问不收集姓名、电话、身份证等不必要信息。

### 4.3 真实细节门槛

真实细节示例：

- 旧电脑开机慢/风扇响
- 宿舍桌面小
- 每天背电脑去教室
- 上网课要同时开课件和笔记
- 剪视频时素材多、导出慢

必须存在以下字段之一才能生成：

- `real_detail.text` 非空
- `real_detail.source = sales_provided`
- `real_detail.confirmed = true`

真实细节进入内容时必须标记为“销售提供的场景”，不得伪装成已核验产品事实。  
没有真实细节时，只能显示“还差一个真实场景”的提示，不能偷偷用模板补。

### 4.4 顾客问答到内容工坊

- 问答是对话流，不是表单页。
- 每轮最多一个问题；关键节点输出结构化卡片。
- 结果卡包含：候选机型、价格依据、限制、应对话术、下一步动作。
- 点击“做成跟进内容”时，只传递：
  - 预算
  - 使用场景
  - 人群/偏好
  - 候选机型
  - 已核验事实 ID
  - 已确认的真实细节
  - 目标动作（到店/私聊/收藏）
- 不传姓名、电话、完整对话、未确认的顾客原话。
- 不做 CRM、跟进状态、下次联系时间。

### 4.5 生成失败与重试

- 五渠道允许部分成功。
- 已成功渠道立即落库并展示。
- 失败渠道显示：失败阶段、原因、是否可重试。
- 重试只重跑失败渠道，不重跑全部。
- 不允许用固定模板伪装“成功”。
- 任务刷新/重新打开要恢复状态。

### 4.6 事实不足时的行为

1. 先查事实账本。
2. 缺失则自动 Tavily 搜索官方来源。
3. 抓取正文、抽取候选事实、校验来源和冲突。
4. 仍不足时生成“安全版”：
   - 不含价格、参数、型号对比、未核验卖点
   - 只讲场景与到店体验
   - 显示可点击的待补项
5. 不允许模型凭常识补全进入可复制内容。

## 5. 视觉与组件规范（Impeccable · Operate）

### 5.1 方向

**华为门店专业工具 / 编辑纸感 / 安静的高密度。**  
不是营销落地页，不是 AI SaaS 模板，不是深色赛博风。

### 5.2 色彩

- 纸面：`#FBF6EF`
- 墨色：`#181818`
- 次级文字：`#6B6257`
- 华为红：`#C8102E`
- 浅线：`rgba(0,0,0,0.10)`
- 成功/警告/错误必须有独立语义色，不能只靠红点。

避免纯黑、纯白、紫蓝渐变、玻璃拟态、彩色底上的灰字、无意义装饰。

### 5.3 字体

- 单一无衬线体系：`PingFang SC` / `Hiragino Sans GB` / 系统字体回退。
- 数字与来源码可使用 `ui-monospace`。
- 不用 Inter、Arial 作为主 UI 字体。
- 标题与正文使用固定 rem 阶梯，不用大面积流体标题。

### 5.4 组件

必须实现完整状态：

- 默认、hover、focus、active、disabled、loading、error
- 触控目标 ≥ 44px
- 焦点环清晰
- 状态变化用 150–250ms 动效
- 不做页面入场编排
- 不使用嵌套卡片充当层级
- 弹层优先 inline / 底部抽屉，不要动辄弹窗

核心组件：

- `BottomNav`
- `TaskCard`
- `ChannelPackCard`
- `PlatformPreview`（小红书/朋友圈/公众号/海报/视频号）
- `VariantTabs`（角度 A/B/C）
- `EvidenceDrawer`
- `RiskBanner`
- `FactBlockModal`
- `DetailQuickChips`
- `VoiceInputButton`
- `ImagePlanSheet`
- `ImageStudio`
- `ExportSheet`
- `StoreProfileForm`
- `AdminDiffTable`

### 5.5 响应式断点

以内容驱动为主，默认：

- `< 768px`：手机单列 + 底部导航
- `768–1023px`：平板两栏
- `>= 1024px`：桌面三栏

必须覆盖：

- 320px 极窄
- 390×844 手机
- 768px 平板
- 1440px 桌面
- 横屏
- 键盘导航
- 粗指针/触屏
- 安全区 `env(safe-area-inset-*)`

### 5.6 PWA

- `manifest.webmanifest`
- 应用图标、主题色 `#FBF6EF`
- Service Worker 缓存应用壳和门店基础配置
- 离线时允许查看最近任务/草稿；生成、搜索、导出需要在线
- 不伪装离线可用生成

## 6. 内容包规格

### 6.1 通用字段

每个渠道输出：

```ts
{
  platform: "xiaohongshu" | "moments" | "wechat-mp" | "poster" | "video",
  angle: "pain" | "avoidance" | "story",
  audience: string,
  scene: string,
  target: string,
  model: string,
  sku?: string,
  systemVersion?: string,
  title?: string,
  titleOptions?: string[],
  summary?: string,
  body: string,
  tags?: string[],
  firstComment?: string,
  cta: string,
  script?: string,
  shotList?: string[],
  imagePlan: ImagePlanItem[],
  evidence: EvidenceRef[],
  limitations: string[],
  status: "writing" | "reviewing" | "blocked" | "ready" | "failed",
  editBurden: "none" | "light" | "heavy",
  verifiedAt?: string
}
```

### 6.2 小红书

- 标题 ≤ 20 字
- 正文 300–800 字
- 3–5 个标签
- 首评一条可复制
- 3:4 封面/配图
- 三个角度各一版
- 默认遵守平台规则卡的 AI 标识要求
- 不写空泛口号；要有具体场景和一处真实细节

### 6.3 朋友圈

- 无标题
- 40–300 字
- 前 6 行内说完关键信息，防折叠
- 1 或 3 张图优先
- 三个角度各一版
- 结尾轻钩子：到店 / 私聊 / 看实物
- 不写长参数清单

### 6.4 公众号

- 标题 ≤ 64 字
- 摘要 ≤ 120 字
- 正文 800–1500 字，含 3 个小标题
- 900×383 封面
- 文末来源说明：信息基准日、官方公开价口径、以门店实际报价为准
- 只 1 版，不铺三候选
- 不复制官方文案长段落，必须改写

### 6.5 海报

- 主标题 ≤ 12 字
- 最多 4 行短句
- 3:4，1242×1656
- 价格默认带官方快照和口径；冲突/过期时阻断
- 预留二维码/地址/电话区域；未配置则留白并提示
- 只 1 版
- 禁止假二维码、假活动期限、假库存

### 6.6 视频号

- 9:16
- 默认 45–60 秒口播，最多 90 秒
- 首 3 秒抓人
- 3–5 个镜头/分镜
- 字幕适配静音观看
- 三个角度各一版
- 结尾自然引导到店或私聊
- 事实、条件、限制必须出现在脚本或分镜中

### 6.7 价格口径

默认带官方起价时统一格式：

> 官方公开价 ¥5,899 起（2026-10-17 官方快照，以门店实际报价为准）

规则：

- 价格必须绑定具体型号和 SKU/配置范围。
- 预算、SKU 条数、活动数字不能当价格证据。
- 冲突未解决：不生成价格字段。
- 价格 stale：触发重新搜索；未解决则阻断价格。
- 价格只允许来自同型号价格事实，不能跨型号、跨配置复用。

### 6.8 真实细节与体验

- 只能写销售提供的真实细节。
- 不虚构顾客姓名、学校、天气、成交、使用天数、对比结果。
- 不把“官方宣传语”改写成第一人称亲测。
- 不虚构“我用了三天”“顾客当场下单”等。

### 6.9 竞品

- 默认不写竞品。
- 如果销售提供竞品官方资料，可进入中性比较。
- 必须有来源、日期、适用型号。
- 不允许贬损、暗示造假、无依据优劣结论。
- 无来源直接阻断。
- 竞品话术只进入顾客问答内部时，可以不进入公开内容。

### 6.10 导出包

ZIP 结构建议：

```text
manifest.json
copy/xiaohongshu.txt
copy/moments.txt
copy/wechat-mp.txt
copy/poster.txt
copy/video.txt
images/...
sources.json
README.txt
```

`manifest.json` 记录：

- 任务 ID、门店、产品、事实版本
- 每个渠道的选中候选、角度、状态、editBurden
- 未生成的图片
- 未解决冲突/待补项
- 生成时间和模型
- 平台规则版本

手机端优先 `navigator.share({ files })`；不支持则下载 ZIP。  
单渠道复制、单图下载始终可用。  
未通过核验的渠道不能复制/导出。

## 7. 事实账本与来源治理

### 7.1 来源等级

1. 具体 SKU 官方规格页 / 官方支持页 / 官方商城（记录 SKU 和日期）
2. 官方产品页 / 官方发布会（用于定位、场景、官方表达，不替代规格字段）
3. 内部知识库中已整理且带原始来源的事实
4. 门店上传的官方资料 / 官方截图
5. Tavily 发现的官方页面（仍需抓正文与核验）
6. 第三方测评、社区、媒体：只作为问题线索，不作为唯一硬事实

### 7.2 每一条事实必须带

```ts
{
  id: string,
  productId: string,
  model: string,
  sku?: string,
  field: string,
  value: string | number,
  unit?: string,
  conditions?: string,
  sourceId: string,
  sourceUrl?: string,
  sourceTitle?: string,
  capturedAt: string,
  publishedAt?: string,
  effectiveFrom?: string,
  effectiveTo?: string,
  status: "active" | "stale" | "conflict" | "rejected" | "superseded",
  trustTier: 1 | 2 | 3 | 4 | 5,
  excerpt?: string
}
```

### 7.3 冲突处理

必须：

- 先核对型号、SKU、地区、页面类型、发布日期、抓取日期、单位。
- 不平均、不拼接、不静默删除。
- 同级冲突保留双方证据，相关字段进入 `conflict`。
- 冲突未解决时，所有引用该字段的内容和价格进入阻断。
- 管理员确认时必须选择：SKU、适用地区、生效日期、来源、结论。
- 所有确认写审计日志。

当前真实案例：

- 内部知识库：MateBook 14 鸿蒙版 ¥5,899 起（2026-10-17 快照）
- 当前官网：¥6,599 起
- 处理：**冻结价格**，管理员核对配置/SKU/页面日期后才能恢复。

### 7.4 Tavily 角色

Tavily 是**来源发现与正文提取工具**，不是事实数据库。

触发：

- 账本无对应事实
- 价格快照过期
- 新品/新活动/新 SKU
- 管理员手动“查官方资料”

行为：

1. 查询模型名 + 字段 + 官方域名。
2. 只接受官方域名或用户明确提供的官方 URL。
3. 抓取完整正文，不能只用搜索摘要。
4. 记录 URL、标题、抓取时间、正文 hash、摘录。
5. 抽取候选事实，标记 `proposed`。
6. 与现有事实做差异/冲突检查。
7. 管理员确认后写入 `active`。
8. 搜索失败/超时：不编造，进入安全版或待补。

### 7.5 数字核验范围

必须核验：

- 价格、官方价、活动价、补贴、赠品、期限
- 屏幕尺寸/材质/分辨率/刷新率/色域/亮度
- 处理器、系统、内存、存储
- 重量、厚度、尺寸、电池、续航、充电
- 接口数量/类型、摄像头、音频、键盘/触控
- SKU 数量、颜色、版本、适配数量
- 保修、售后、库存、活动条件
- 竞品比较中的所有数字和结论

不需要强制核验：

- “3 个技巧”“两天”“第一步”等普通叙述数字
- 预算数字，但不能把它写成产品价格
- 门店地址/电话，但必须来自门店配置

核验实现：

- LLM 低温度抽取 claim 列表
- 规则归一化数字、单位、型号、SKU
- 在同型号、同 SKU、同字段、同单位、同条件下匹配
- **禁止字符串包含式自证**
- 每条 claim 返回：`supported` / `unsupported` / `conflict` / `stale`
- `unsupported|conflict|stale` 默认阻断复制/导出
- 提供精确 span、原因、已有证据、修复动作
- 不允许模型自行判定“事实通过”

## 8. AI 与 Agent 架构

### 8.1 内部角色（不在 UI 表演）

- **Planner**：选题、缺失信息、图片计划、渠道结构
- **Researcher**：知识库 + Tavily + 事实账本
- **Writer**：平台化写作，三角度
- **Reviewer**：真人感、具体细节、平台适配、结构
- **Deterministic Verifier**：代码核验，不是 Agent，不可被提示词绕过

### 8.2 模型路由

- 创意写作：`deepseek-v4-pro`，temperature 0.8–0.9
- 规划/问题生成：`deepseek-v4-pro`，temperature 0.2
- 评审：`deepseek-v4-pro`，temperature 0.2
- 事实抽取/字段分类：`deepseek-v4-pro` 或 `deepseek-chat`，temperature 0.1–0.2
- 事实核验：代码 + 低温度结构化抽取，不允许模型单独判定
- 创意生成 `max_tokens` 建议 6000–8000
- 处理 `reasoning_content`：空 `content` 时重试或读取有效输出
- 空响应、截断 JSON、格式错误都要重试一次

### 8.3 多候选

- 小红书/朋友圈/视频号各 3 个角度：痛点、避坑/选择、真实故事。
- 公众号/海报各 1 版。
- 三版共享同一事实快照和同一真实细节。
- 评审器按“真人感、具体细节、平台适配、结构完整、无套话”评分。
- 系统选择推荐稿；销售可换、可融合。
- 融合后必须重新事实核验。

### 8.4 去 AI 味

检测目标：

- “赋能、打造、引领、重新定义、在这个时代、无论是……还是……”
- 空泛形容词堆叠
- 首段模板化自我介绍
- 三段式“首先/其次/最后”
- 过度对仗、过度排比
- 无具体动作和细节
- 过多 emoji、过多感叹号
- 像官方新闻稿而不是门店销售说话

处理：

- 标出具体句子和问题类型
- 给出替换建议
- 一键改写
- 改写后重新核验
- 不静默替换原意
- 区分“AI 味”和“平台正式文体”：公众号可以更正式，但不能空泛

### 8.5 门店口吻

- 首次配置可粘贴 1–3 条门店真实历史文案。
- 提取：句长、常用词、称呼、情绪强度、emoji 使用、开头/结尾习惯。
- 提取结果只影响表达，不影响事实。
- 跳过时回退到轻量配置：店名、城市、直接/温和、简短/详细。
- 样本按门店隔离，不跨店使用。
- 不复制历史文案原文，不把顾客信息带入新内容。
- 门店实拍/历史文案需有授权确认。

## 9. 图片工作室

### 9.1 原则

- 产品本体只能来自官方素材或门店实拍。
- AI 只生成背景、光影、构图、环境。
- 不允许 AI 生成产品外观、屏幕内容、Logo、接口、键盘布局。
- 文字、价格、标签、门店信息由模板层绘制。
- 不生成假二维码。
- 图片数量由规划器决定，不询问销售。

### 9.2 图片计划

规划器输入：

- 渠道
- 场景
- 选中候选数量
- 需表达的信息
- 可用官方产品图
- 是否有门店实拍/二维码/联系方式
- 平台比例与规则

输出：

```ts
{
  purpose: "cover" | "detail" | "scene" | "poster" | "video-cover",
  ratio: "3:4" | "1:1" | "16:9" | "9:16",
  width: number,
  height: number,
  productAssetId: string,
  backgroundBrief: string,
  overlayText: string[],
  required: boolean
}
```

默认最低量：

- 小红书：3 张（封面 + 2 张内容图）
- 朋友圈：1 张（最多 3 张）
- 公众号：1 张 900×383 封面
- 海报：1 张
- 视频号：1 张 9:16 封面

规划器可以在素材不足时减少非必要图，但不能生成假产品图。

### 9.3 合成流程

1. 选择官方透明产品图 / 门店实拍。
2. 规划背景（无设备、无品牌、无文字）。
3. AI 生成背景。
4. 产品抠图/缩放/整体透视/接触阴影/环境光轻微适配。
5. 模板层绘制标题、标签、价格、门店信息。
6. 图片质量检查：是否出现其他设备/竞品 logo/假文字/产品形变。
7. 保存合成参数与素材来源。

### 9.4 质量底线

- 产品比例、结构、Logo、接口、键盘不得改变。
- 背景不得出现其他电脑、手机品牌、假二维码。
- 模板文字必须可编辑、可重新导出。
- 图片必须保留产品素材 ID 和背景提示词，便于追溯。
- AI 场景生成失败不影响文案交付。

当前验证发现：AI 自由生成校园场景时自动生成了 Apple 笔记本，因此必须显式负面提示 + 合成后检查；不能把“提示词排除”当作唯一保障。

## 14. 验收用例

### 14.1 事实与红线

1. 无真实细节 → 生成按钮禁用，提示缺什么。
2. 输入“预算 6000” → 不能被当成产品价格事实。
3. 写“¥4,999”但账本无依据 → 标红、禁止复制/导出。
4. 官网价格 6,599 与知识库 5,899 冲突 → 冻结价格，不能生成带价内容。
5. 管理员确认具体 SKU 与日期后 → 对应价格恢复，旧版本保留审计。
6. 输入竞品口头评价、无官方来源 → 阻断。
7. 上传竞品官方页并核验 → 只允许中性陈述，不允许贬损。
8. AI 图片中出现其他品牌电脑/假二维码 → 图片不可用。
9. 未配置门店二维码 → 海报留白并提示，不生成假码。
10. 官方图缺失 → 不允许 AI 生成产品外观，改为上传/换素材。

### 14.2 内容质量

1. 五渠道都存在且结构不同，不是同一稿换标题。
2. 小红书/朋友圈/视频号各三版，三版角度可辨。
3. 公众号 800+ 字、3 个小标题、来源说明。
4. 海报 12 字内主标题、4 行短句、3:4。
5. 视频号 45–60 秒口播、9:16 封面、首 3 秒钩子。
6. 至少一处销售真实细节，且未被写成官方事实。
7. 评审器判定“最多轻改一次”；如需大改，任务失败并说明原因。
8. 去 AI 味建议精确到句子，不静默改稿。
9. 融合两版后重新核验。

### 14.3 交互与设备

1. 390×844 手机完成：首页 → 追问 → 五渠道 → 选稿 → 按需生图 → 导出。
2. 768px 平板两栏可用。
3. 1440px 桌面三栏可用。
4. 320px 不横向溢出。
5. 触控目标 ≥ 44px；无 hover-only 操作。
6. 刷新生成页后恢复任务状态。
7. 单渠道失败可重试，其他渠道不重跑。
8. 顾客问答一键转内容，不携带姓名/电话。
9. 7 天后顾客问答不可恢复。
10. PWA 可安装，离线可看最近任务，生成需联网。

### 14.4 导出

1. ZIP 含五渠道文案、已生成图片、sources.json、manifest.json。
2. 未通过核验的渠道不进 copy 目录，manifest 标注 blocked。
3. 手机支持文件分享时调用系统分享，否则下载。
4. 单渠道复制与单图下载可用。
5. 导出包中能看到事实版本、来源、生成时间、模型和待补项。

### 14.5 搜索

1. Tavily 能搜索官方域名。
2. 搜索结果只作候选来源，不直接入库。
3. 抓不到正文时不生成事实。
4. 超时 20 秒进入待补/安全版。
5. 管理员确认页面显示原文、URL、抓取时间、差异。

## 16. 演示数据与合规标注

必须明确标注：

- 虚构顾客：`演示场景 · 非真实顾客`
- 产品事实：`官方公开信息 · 快照日期 YYYY-MM-DD`
- 冲突未解决：`待确认 · 不作为发布依据`
- AI 生成背景：导出 manifest 记录，不伪装成门店实拍
- 门店实拍：必须有授权确认
- 竞品资料：必须有官方来源和日期

不得出现：

- 真实顾客姓名/电话/学校
- 虚假成交、虚假评价、虚假门店活动
- 假二维码、假地址、假库存
- “全网最低”“第一”“绝对”等无依据表达
- 把 AI 生成图说成真机实拍
- 把官方公开价说成门店成交价
